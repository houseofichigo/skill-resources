Pick the model last
The seven questions

Stop at the first one that decides it

Earlier questions outrank later ones. A hard tool requirement beats any amount of model quality.

01
Does the answer depend on information that can change?
Yes → live search is mandatory, and citations too if anyone will check the claims. A model without search answers confidently and wrongly.
02
Is the work tied to a particular environment?
Drive, SharePoint, a repository, a database — whatever reaches the data wins. Integration outweighs a modest quality difference.
03
How many files, and how long?
A few: attach them. One very long one: long-document handling. Dozens: file search. Thousands: an indexing project, not a chat.
04
What is in the input besides text?
Charts, scans, audio, video. Check this before comparing intelligence — a smarter model that cannot see the chart is useless.
05
How hard is the thinking, honestly?
Routine work on the flagship wastes money. Client-facing work on the cheap tier costs more the first time someone has to fix it.
06
Which constraint actually binds — quality, speed or cost?
One usually dominates. Name it, optimise for it, and say what was traded away.
07
Is the data sensitive or regulated?
A hard gate, not a preference. Use what the organisation has approved, even when it is the weaker tool.
Tier translation

Three practical rungs, without fixed price bands

Most lineups fit this ladder. Names and price gaps change, so look them up before recommending a model.

RungWhat it is forCost tendency
Fast / light High volume and repetitive: classification, extraction, short summaries, quick answers. Most automated work belongs here. Lowest
Balanced Most real work: drafting, analysis, everyday coding, document work. This is the default for a working professional. Higher
Frontier Hard reasoning, architecture, long autonomous runs, and anything where being wrong is expensive. Reach for it deliberately. Highest

Provider price gaps vary too much for one multiplier. Verify current pricing and measure cost per successful task. In consumer apps this ladder often appears as a thinking control — fast, think harder, maximum.

Six things people get wrong

Rules of thumb

Cost per successful task, not per token
A cheap model that retries twice and needs a human fix is the expensive one.
“Analyse this PDF” is not one task
A summary, one exact fact, a table, a chart reading and a judgement route to four different setups.
A big context window is not comprehension
Fitting the text in is not the same as reasoning well over all of it.
Benchmarks shortlist, they do not decide
Run three real examples through two candidates. Ten minutes beats any leaderboard.
“Write code” is four different jobs
One function, a bug hunt, a repo-wide refactor and an architecture review need different setups.
Do not switch provider for a few points
Connectors, ecosystem fit and the subscription already paid for usually matter more.

The strongest model is rarely the right one.

Route by what the task requires, not by what scores highest. Then verify the names — lineups, tiers and prices change monthly, and anything printed on paper is already going stale.
